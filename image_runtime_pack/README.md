# Image addon on local worker disk

This candidate reuses the sealed Python/native addon archive. The original Comfy runtime, Python packages and models stay on the network volume. It does not build a new full-runtime archive or change the existing seals.

The archive is `mdcln-runtime-addons/cpython-3.12.12-20260211.tar.gz`, 386,050,882 bytes, SHA-256 `f450987ebd185afca9218d1062ff1e9bef2fb7f86179c8089840d1eff82311de`. Provision exactly these bytes on both `mevpt9ccol` (EU-RO-1) and `d4ki71blpr` (US-IL-1), checking size and streamed SHA before atomic publication. The serving image remains the pinned Ubuntu 22.04 image from `image_python_addon/README.md`. No package installation or certificate download occurs at boot.

Run `python3 -B image_runtime_pack/build_manifest.py` to obtain the four launcher files, their hashes and the immutable staging directory. Stage those files to that directory on each volume without replacing a different file. `production_launch.sh` is the exact outer command for the recorded candidate: its file hashes must agree with a newly generated manifest before use. Encode the full command as plain `bash -lc 'printf %s BASE64 | base64 -d | bash'` provider arguments. Preserve the live template's remaining configuration and `NSFW_COMFY_BYPASS_UPSCALE=0`; a changed upscale policy requires a new reviewed candidate.

The bootstrap checks the existing TLS bundle, sealed manifest identities, twelve critical runtime files, and bootstrap interpreter/library. It copies the archive to private local scratch, authenticates the same open file descriptor it extracts, rejects path escapes, external aliases except the fixed package link, symlink parents, duplicate members and unsupported types. Each boot gets a new owned local instance, so an interrupted extraction cannot be reused or block the next attempt. All extraction finishes before execution. Only local venv paths are rewritten. `PYTHONDONTWRITEBYTECODE=1`, `-B`, `SSL_CERT_FILE` and `REQUESTS_CA_BUNDLE` are set before application Python.

The local launcher checks ABI/package metadata but does not import Torch. `checked_comfy.py` preserves Comfy's normal import order and asserts Torch 2.8.0+cu128, CUDA 12.8 and available CUDA once its first Torch import completes. It runs the original `main.py` in that process. The original `start.sh` is checked and copied locally; only Python's `-B` flags and the Comfy entry wrapper differ. The handler and full production node/model preflight remain in place.

Benchmark-only profiling tools and raw proof files live in the operator workspace, outside this serving-code directory. The profiler uses `profile_comfy.py --local-addon INSTANCE/addon --checked-comfy STAGED/checked_comfy.py`. It checks all 28 types, 22 custom-node directories and 16 models, including upscale, and never imports the job handler. Its Python audit hook blocks volume writes and external Python sockets; this is not a kernel filesystem sandbox. Logs and object-info ownership are retained, then the owned process group is stopped. Keep CPU timings separate from provider queue, GPU boot and inference timings.

The shared CPU baseline measured 52.451 seconds for the old full-addon checksum and 29.627 seconds for its separate Torch import. Initial local CPU preparation took about 12 seconds. CPU cache state differed between runs; these measurements do not establish GPU cold-start savings. Both placements require fresh fixture03 GPU/artifact/boot proof before production promotion. Historical thin GPU proofs do not qualify this new launcher. The production command has no fixture HTTP server; use the previously verified fixture01 with LoRA disabled for the owned production check.

Run the scoped regression checks with `python3 -B -m unittest discover -s tests -p 'test_image_local_addon.py'`. The operator also tests archive/build/placement evidence, actual GPU-process markers, protected configuration and rollback. No warm workers are introduced.
